# G&W 改造ツール（ゼルダ / マリオ）

「ゲーム＆ウオッチ ゼルダの伝説」と「ゲーム＆ウオッチ スーパーマリオブラザーズ」を **純正ファーム + Retro-Go のデュアルブート** にする作業を、GUI で実行する Windows 用ツールです。ビルドから ST-Link での書き込みまで、すべてこのアプリから行えます。

- 純正側: [game-and-watch-patch](https://github.com/BrianPugh/game-and-watch-patch)
- エミュレータ: [game-and-watch-retro-go (sylverb)](https://github.com/sylverb/game-and-watch-retro-go)
- 書き込み: [gnwmanager](https://github.com/BrianPugh/gnwmanager) + OpenOCD（ST-Link）

## 前提

- Windows 10/11、Python 3.9 以上、[Git for Windows](https://git-scm.com/download/win)
- ST-Link（USB ドライバ STSW-LINK009）
- 本体はアンロック済みで、純正ファームのバックアップを吸い出し済みであること
  （Zelda: `internal_flash_backup_zelda.bin` 128KB / `flash_backup_zelda.bin` 4MB、
  Mario: `internal_flash_backup_mario.bin` 128KB / `flash_backup_mario.bin` 1MB）

make・ARM GCC・OpenOCD・Python 依存パッケージは、アプリが `tools\` 以下に自動で導入します。

**持ち運び版（別の PC で使う）**: `python scripts\make_portable.py` を実行すると、このフォルダの隣の `game_watch_kai\`（出力先は引数で指定可）に「フォルダの中だけで完結する版」ができます。Python・Git・ARM GCC・OpenOCD・ソース・ROM・バックアップ・セーブ・設定をすべて同梱し、`GnW改造ツール.exe` で起動します。フォルダごとコピーすれば、Python や Git が入っていない PC でも動きます（PC ごとに要るのは ST-Link の USB ドライバだけ）。大きさは約 2〜3GB です。

対応している機種と、ROM を用意するときの注意点は [manual.md](manual.md) にまとめています。

## 使い方

**起動方法**

- デスクトップの **「GnW改造ツール」** アイコンをダブルクリックする
  （ショートカットが無い場合や、フォルダを移動した場合は `ショートカット作成.bat` を実行すると作り直せます）
- または、このフォルダの `GnW改造ツール起動.bat` をダブルクリックする

起動に失敗した場合はエラーダイアログが表示され、詳細が `error.log` に保存されます。

起動したら、画面上部で **改造する本体（ゼルダ / マリオ）** を選んでから、タブを順に進めます。
バックアップのフォルダと外部フラッシュの容量は、機種ごとに別々に記憶されます。

1. **環境セットアップ**: 「すべて自動セットアップ」を押す（初回は数分かかります）
2. **バックアップ**: バックアップのフォルダを指定する。純正ファームの SHA1 と照合されます
3. **構成**: 外部フラッシュの容量（純正 4MB / 換装後の容量）と各オプションを選ぶ
4. **ROM と容量**: `roms\<機種>\` に ROM を入れる。書き込めるかどうかを自動で計算して表示します
5. **ビルド & 書き込み**: 書き込む内容を選んで「ビルドして書き込む」を押す
   - **純正ファーム**（① 外部フラッシュの純正データ + ② 内部 Bank1）: 初めて改造する本体のみ必要です
   - **Retro-Go**（③ 内部 Bank2 + ④ 外部フラッシュの Retro-Go 領域）: 改造済みの本体で ROM や設定を変えたときは、これだけ書き込めば十分です
   - ③と④は分けられません。ROM の一覧表が③に入るため、④だけを書くと食い違って起動しなくなります
   - ④は本体の内容と比較して、変わったブロックだけを書き換えます

書き込みが終わると、通常起動で純正ファームが、**十字キー左 + GAME** で Retro-Go が起動します。

## 保存ビルド（builds\*.gnw）

ビルドするたびに、書き込み用のデータ一式を **1つのファイル** にまとめて `builds\` に保存します。書き込みは、ビルド直後でも後からでも、必ずこのファイルを検証してから行います。

- 中身: 純正（① 外部フラッシュ先頭 / ② 内部 Bank1）、Retro-Go（③ 内部 Bank2 / ④ 外部フラッシュ / セーブ位置を調べるための ELF）、機種・書き込み位置・ROM 一覧・各ファイルの SHA256
- ③④ は同じビルドの組でしか動かないため、常に同じファイルに入れて扱います
- 「保存済みビルド」から選ぶと、過去のビルドをビルドし直さずに書き込めます。ファイルが壊れている場合、または機種・外部フラッシュの書き込み位置・容量が今の設定と合わない場合は、書き込めません
- 選んだ領域は、gnwmanager の 1 回の接続でまとめて書き込みます
- ★ は、その本体に最後に書き込んだビルドです

## セーブデータ

セーブの位置は、ビルドに入れた ROM の構成で決まります。

- **自動引き継ぎ**: ROM 構成が変わってセーブの位置がずれる場合は、前回書き込んだビルドの情報で現在のセーブを吸い出します。新しいビルドを書き込んだ後、ROM 名が一致するゲームへ書き戻します。吸い出したデータは `saves\<機種>\<日時>_書き込み前\` に残ります
- **バックアップ / 書き戻し**: ⑤の「ツール」から、本体に書き込まれているビルド（★）の情報を使って `saves\` へ吸い出したり、書き戻したりできます
- このツールで一度も書き込んでいない本体は、書き込まれているビルドが分からないため、初回の書き込みではセーブを引き継げません

## 機種ごとの違い

| | ゼルダ版 | マリオ版 |
|---|---|---|
| 純正の外部フラッシュ | 4MB | 1MB |
| パッチ（純正チップのまま） | `--device=zelda --no-la --no-sleep-images`（夢をみる島・スリープ画像を削除） | `--device=mario --internal-only`（純正ファームを内部フラッシュだけに収める） |
| パッチ（容量増設時） | `--device=zelda`、Retro-Go は 4MB 目以降を使用 | 既定では `--internal-only` で外部フラッシュ全体を使用。隠し要素を残す設定にすると先頭 1MB を純正に使用 |
| Retro-Go のメニュー配色 | 緑系 | 赤系 |
| ボタン | GAME=START、TIME=SELECT、PAUSE/SET=メニュー。本体の START/SELECT は追加ボタン (X/Y) | START/SELECT ボタンが無い |

Retro-Go は `GNW_TARGET` によって配色とボタンの割り当てを切り替えます。必ず改造する本体と同じ機種を選んでください。
マリオ版の `--internal-only` では、スリープ画像とマリオの歌の隠し要素が削除されます。また、Retro-Go を起動して戻るとハイスコアや明るさ・音量の設定が保持されません。

## 容量の計算

Retro-Go が外部フラッシュに書き込む内容を、ビルドせずにその場で計算します。

- ROM データ: Retro-Go と同じ方式で LZMA 圧縮した後のサイズ（GB は 16KB バンクごと、SMS/GG/MD/COL/SG は圧縮なし）
- セーブ領域: ROM ごとに確保される量（GB はカートリッジヘッダから、NES はマッパーから算出）
- エミュレータコード: ROM を入れた機種の分だけ加算
- フォントと機種別の固定データ（日本語の CODEPAGE=932 で +208KB、NES を入れると +39KB、SMS/GG/SG/COL で +8KB）
- カバー画像（有効時）: ビルドと同じ JPEG 変換を行った後のサイズ

この計算式は、ダミー ROM を使った実ビルドの結果（ゼルダ版・マリオ版の両方）とバイト単位で一致することを確認済みです。ただし MSX / Amstrad のエミュレータサイズは推定値です（BIOS 等が無いと計測できないため）。
「試しビルドで正確に確認」を押すと実際にビルドして、リンカが出力する正確な値を表示します。

## カバー画像（パッケージ画像）

ROM と同じフォルダに、**同じファイル名**で画像を置きます（png / jpg / jpeg / bmp）。

```
roms
es\Zelda.nes
roms
es\Zelda.png   ← Zelda.nes のカバー
```

- ③構成で「カバーアート表示」を有効にすると使われます（Retro-Go の `COVERFLOW=1`）
- ビルド時に **128×96 へ縦横比を無視して引き伸ばされ**、JPEG（品質は ③構成で指定、既定 90）に変換されて外部フラッシュに格納されます。4:3 の画像を用意するときれいに表示されます
- 1 枚あたり数 KB です。容量計算にはビルドと同じ変換を行った後のサイズが反映されます
- 画像が無い ROM はカバー無しで表示されます（エラーにはなりません）
- ④タブで ROM を選ぶと、実機での見え方をプレビューできます。ROM と名前が合わない画像は警告されます

### カバー編集（トリミング・貼り付け）

④タブで ROM を **ダブルクリック**、プレビューを **クリック**、または ROM を選んで **Ctrl+V** を押すと、編集画面が開きます。

- 画像の取り込み: 既存のカバー、「ファイルを開く…」、**クリップボードからの貼り付け (Ctrl+V)**。ブラウザでコピーした画像にも、エクスプローラーでコピーした画像ファイルにも対応します
- トリミング: 枠の中をドラッグで移動、四隅をドラッグで拡大縮小、枠の外をドラッグで範囲を描き直し、ホイールで拡大縮小、ダブルクリックで最大
- 縦横比は実機のカバー比率 (128:96) に固定できます（既定でオン。歪みません）
- **元画像の比率を保つ（黒帯）**: 「全体を収める（黒帯）」で、画像全体が入る 4:3 の枠に合わせます。足りない部分は黒で埋まります（縦長なら左右、横長なら上下）。「画像の外側も範囲にできる」がオンなら、枠を画像の外まで広げたり動かしたりできます。この設定は記憶され、新しく取り込んだ画像は「全体を収める」状態で開きます
- 「画面いっぱい（切り抜き）」は、画像の内側で最大の 4:3 範囲を切り抜きます（黒帯なし）
- **余白の塗り**: 黒 / 白 / ぼかし（元画像を拡大してぼかしたもの） / Retro-Go の各配色の背景色 / 任意の色 から選べます
  - カバーは JPEG に変換され、不透明な四角として描かれるため、本当の透過はできません
  - 余白を **Retro-Go メニューの背景色** にすれば、背景と同化して透過と同じ見た目になります。標準の配色（1〜6）は背景が黒なので、既定の「黒」でそのまま同化します
  - 左右に並ぶ脇のカバーは Retro-Go が暗くして描くため、色付きの余白は背景よりわずかに暗く見えます（黒ならずれません）
- 右側に、実機と同じ JPEG 変換後の見え方（2倍表示）と書き込みサイズを表示します
- 保存すると、トリミング結果を `<ROM名>.png` として ROM の隣に置きます。元画像とトリミング範囲は `.cover_originals\` に残るので、後から何度でもトリミングし直せます

## フォルダ構成

| パス | 内容 |
|---|---|
| `gnwtool\` | アプリ本体（Python / Tkinter） |
| `roms\` | ROM の置き場所。ビルド時に retro-go へ同期されます |
| `backup_rom\` | 純正ファームのバックアップ（**別の場所にも保管してください**） |
| `tools\` | 自動導入されたツール（削除すれば再導入できます） |
| `workspace\` | patch / retro-go のソースコード |

## 注意

- ST-Link の 3.3V と本体の VDD は接続しないでください（接続するのは GND / SWDIO / SWCLK のみ）
- ROM・BIOS は、ご自身が所有するソフトから吸い出したものを使用してください
- 「純正ファームに戻す」を実行すると、Retro-Go とそのセーブデータは消去されます
